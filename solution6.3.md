With overflow visible, which is the default, the extra content spills outside the container and overlaps other elements without any scrollbar, which can break the layout. With overflow hidden, the overflowing content is simply cut off and becomes invisible, which hides information from the user. With overflow scroll, scrollbars always appear both horizontally and vertically even when not needed, which looks unnecessary. With overflow auto, the browser intelligently adds scrollbars only when the content actually overflows, which is the most recommended and user-friendly approach. In the second part, I created a separate scrollable content box with a fixed height of 200px and used overflow auto, making it perfect for use cases like chat windows, comment sections, or article previews where content length is unpredictable. In the third part, I identified a common overflow issue in a sample page where a very long word and a large image with width larger than its container caused horizontal scrolling and broke the mobile layout. To fix this issue, I applied three solutions: I set overflow auto on the container to contain scroll inside, I used word-wrap break-word and overflow-wrap break-word to break long words, and I set max-width 100% and height auto on images so they never exceed the container width.
